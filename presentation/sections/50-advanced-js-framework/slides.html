The DOM

Where an event is caught

A click on a button is also a click on everything around it. The phase decides who hears it first.

setup() {
    useListener(document.body, "click",
        () => this.clicker.addClick(1),
        { capture: true },
    );
}
  • CaptureDown from the document. You hear the click before the button does.
  • BubblingBack up. t-on-click listens here, and a handler can stop the trip.
  • CleanupuseListener removes it when the component goes. addEventListener does not.

Step 2 of the exercise uses exactly this call, capture included.

The toolbox

Talking to the user

Four standard ways. None of them is a component you have to write.

notification = usePlugin(NotificationPlugin);
effect = usePlugin(EffectPlugin);
dialog = usePlugin(DialogPlugin);

// a toast, top right
this.notification.add("A bot was bought", {
    type: "success",
});

// a rainbowman, for a milestone
this.effect.add({ message: "1000 clicks!" });

// a dialog
this.dialog.add(ConfirmationDialog, {
    body: "Reset the game?",
    confirm: () => this.reset(),
});
  • NotificationShort, non-blocking. sticky: true when it must be dismissed by hand.
  • EffectThe rainbowman. Reserved for something worth celebrating.
  • DialogA component in a modal, stacked and closed by the plugin.
  • Tooltipdata-tooltip in the template, or a template of your own with data-tooltip-template.

All three under @web/core: notifications/notification_plugin, effects/effect_plugin, dialog/dialog_plugin. The clicker game uses every one of them.

Assets

Everything under static/ is served

Two ways into the browser: the page fetches the file by url, or a bundle carries it.

  • static/srcYour javascript, scss and xml templates. Bundled, never fetched one by one.
  • static/libA third-party library, as it was downloaded. Bundled too, or loaded on demand with loadJS.
  • static/imgImages and fonts. Fetched by url, when something on the page asks for one.
  • static/testsTest files, in a bundle the web client never loads.

No controller and no access rule in front of it: /my_addon/static/img/logo.png is a public url. Nothing private goes under static/.

Assets

Bundles

  • A bundle is an ordered list of files — js, scss, css, xml — declared in __manifest__.py.
  • Your code runs because it is in one. Nothing else loads it.

my_addon/__manifest__.py

{
    'assets': {
        'web.assets_backend': [
            'my_addon/static/src/**/*',
            ('remove', 'my_addon/static/src/heavy/**/*'),
        ],
        # a bundle of your own, loaded when it is needed
        'my_addon.heavy': [
            'my_addon/static/src/heavy/**/*',
        ],
    },
}
  • web.assets_backendThe web client. Nearly everything written in this training.
  • web.assets_frontendThe public website: another application, another bundle.
  • web.assets_unit_testsTest files, run by hoot, out of the way of the client.
  • your ownAny name you like. LazyComponent loads it the first time a screen needs it.

Ordered, and editable: ('before', …), ('after', …), ('replace', …) and ('remove', …) place a file, or take one out of a bundle you do not own.

The toolbox

Components you should not rewrite

The web client ships a small library of generic components. Look there first.

  • ComponentWhat it doesWhere
  • DropdownA toggle and a menu, with the keyboard handled.@web/core/dropdown/dropdown
  • NotebookTabs, from a list of pages or from slots.@web/core/notebook/notebook
  • PagerPrevious, next, and the count.@web/core/pager/pager
  • CheckBoxA checkbox with its label, and the click zone right.@web/core/checkbox/checkbox
  • LayoutThe control panel, for a screen of your own.@web/search/layout

The formatters in @web/core/utils/numbers and @web/core/l10n save the same kind of work.
